# Отчёт: постобработка OCR паспорта РФ

## Подход

Каждый документ проходит конвейер из двух независимых каналов: визуальной зоны
(10 полей с посимвольными confidentностями) и МНР (машинночитаемая зона).
Решение «принять» выносится только если каждое поле подтверждено или
скорректировано, а паспорт действителен на 01.10.2026. Политика коррекции
консервативна: поправка поля требует минимум два независимых источника
(МНР + контрольная цифра/справочник/формат); при конфликте «оба канала уверены,
но расходятся» документ отклоняется — ложное принятие дороже отклонения.

Структура МНР расшифрована эмпирически по train (совпадение с разметкой
97–99,8% на чистых строках 2×44): строка 2 = серия(2) + 1-я цифра второй пары
+ номер(6) + контр.цифра + RUS + дата рождения + контр.цифра + пол + заполнители
+ **вторая цифра второй пары серии (поз. 28 — не контрольная цифра!)** + дата
выдачи + код подразделения + контр.цифры (позиции 9/19/42/43 — стандарт
ИКАО 7-3-1). Строка 1 = PNRUS + имена в цифровой транслитерации (Й→Q, Ч→3,
Ш→4, Щ→W, Ь→9, Ю→7, Я→8…), выведенной по выравниванию с разметкой (все буквы
≥99%, кроме Щ 98% при 70 вхождениях в train). Таким образом МНР верифицирует
все 10 цифр паспорта, обе даты, пол, код подразделения и все три имени.

## Ключевые находки

- **conf не отделяет ошибки**: 580 из 1811 ошибочных полей train имеют
  conf > 0.99. Пороги по уверенности — тупик; спасает перекрёстная проверка.
- **80% ошибок — одна замена символа** (1451/1811), т.е. исправимы через МНР.
- **Е/Ё слепота МНР**: обе кодируются как «E», имя с «Ё» фактически
  непроверяемо — принимается только при посимвольном conf ≥ 0.999
  (единственное настоящее «Ё» в train: 0.9991; три ошибки: 0.25–0.98).
- **Коррелированные ошибки viz+МНР** — принципиальный предел метода: оба
  канала читают одни и те же пиксели и ошибаются одинаково (2 документа train:
  «ЛЯМПЕРЧИК»/«ЛЯНПЕРЧИК», «КИТУРКО»/«КИТУРКС»). Все измеренные детекторы
  бессильны (см. Amendment Log в plan/stages.md) — эти 2 документа остаются
  единственными ложнопринятыми на train.
- **Справочник DaData не покрывает формулировки разметки** (41/600 точных
  совпадений) — пул кандидатов собран из разметки train ∪ CSV, сверка
  organisation — только точное совпадение (коррекция с расстоянием 1 ловит
  соседние почти-дубликаты: «ОБЛ»/«ОБЛ.», «ОТДЕЛЕНИЕ»/«ОТДЕЛЕНИЕМ»).
- **Место рождения не дублируется нигде** — проверяется алфавит, conf каждого
  символа (включая пробелы: низкий conf пробела = потерянная точка) и
  структура: маркер населённого пункта в начале, административный токен в
  конце, «выпадение точки» (РЕСП→РЕСП.), «склейка/выпадение символа» в слове
  рядом со словарём мест train (ЧСЕВЕРНАЯ→СЕВЕРНАЯ, НИЖЕВАРТОВСК→НИЖНЕВАРТОВСК).

| Сценарий | Принято | Ложнопринято | Неверных по действительности |
|---|---|---|---|
| leave-one-out (честный) | 524 (17.5%) | 2 (семейство выше) | 0 |

Все 105 недействительных паспортов train (правило 14/20/45 лет) отклонены.
Выход детерминирован (повторные запуски — идентичный sha256), только stdlib,
без сети.

## Прогноз для test (обязательный)

- **Будет принято: 293 документа из 2000** (14.6% — фактический прогон;
  зажат между фолд-оценкой 13.5% и LOO-оценкой 17.5%).
- **Из принятых окажутся с ошибкой: 0–3, точечная оценка 1.** Обоснование:
  единственный неустранимый источник — коррелированные замены viz+МНР:
  2 на 3000 документов популяции (0.067%), на 293 принятых — ожидание ≈ 1
  (масштабирование по доле принятых: 2 × 293/524 ≈ 1.1). Новых семейств ошибок
  фолд-проверка не выявила; действительность (70 ожидаемых недействительных
  паспортов в test) отсекается жёстким правилом с нулём ошибок во всех
  экспериментах.
